# 模块化无人机与多机协同：论文调研

本仓库只研究一个问题：**由多个「单旋翼倾转模块」绑缚成一体、协同搬运货物的飞行器，如何靠模块间通信、相对定位、测力与分布式控制稳定飞行，并在模块故障或构型变化时保持可控。**

这不是一份泛泛的多智能体综述。每篇论文都标注它对应你系统里的哪个部件（飞控、ESP-NOW、UWB、测力计、绑缚结构、协同层），作者报告的数字与实验条件单独标出，我们的推断单独标出。

## 目标系统画像

| 维度 | 现状 |
| --- | --- |
| 模块 | 单旋翼 + 倾转机构，一个模块一个飞控 |
| 机载计算 | ESP32-S3 XIAO |
| 模块间通信 | ESP-NOW（2.4 GHz，无 IP，广播/单播，无原生测距与时间同步） |
| 相对定位 | UWB 测距 |
| 力感知 | 测力计，测绑缚点载荷 |
| 任务 | 多模块绑缚货物协同飞行；后续可能改变耦合方式 |
| 控制层级 | 模块内环（姿态/角速率）+ 模块间外环（协同、分配、编队） |

这套系统的三个硬约束，决定了调研重点：**通信带宽低且无时间同步、单模块推力方向受限（倾转单旋翼）、模块间存在力学耦合（绑缚点力）**。

## 结论速览

1. **测力计是这套系统里最被低估的传感器。** 多篇工作（GPAC、桌面力学、单旋翼协同搬运）用局部力/缆张力估计自己应承担的载荷份额，从而把协同降级为"隐式协调"，通信只剩避撞或慢速状态广播。对 ESP-NOW 这种低带宽链路，这比提高通信频率更现实。
2. **单旋翼模块协同搬运已有直接先例，不是空白。** Oishi 等人的三篇工作用多个刚性连接的单旋翼机器人搬运未知货物，实验做到 8 台、约 3 kg、1.6–1.76 m 货物，并演示了机器人失效下的继续飞行。
3. **模块化构型必须与控制一起设计。** MARS 系列把整机抽象成"虚拟四旋翼 + 可行力旋量多面体"，再做预测分配；H-ModQuad 用驱动椭球/力旋量多面体比较不同构型。构型决定可控性，控制器不能事后补。
4. **通信要按网络化控制系统设计，不是"能发包就行"。** 采样周期、时延、丢包、量化、时间同步必须和控制器一起定；并发传输、网络编码、优先级调度都有可借鉴的实测结果。
5. **容错要定义在中间构型上。** 重构过程中的过渡结构可能不可控；已有工作把"每一步重构的可控性裕度"作为约束来规划拆装顺序。
