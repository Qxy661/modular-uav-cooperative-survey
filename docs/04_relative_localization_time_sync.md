# 04 相对定位与时间同步

> 本章回答：UWB 测距如何变成模块间相对位置；ESP-NOW 广播的状态怎么和测距融合；没有时间同步会错在哪；几百个模块时怎么扩展。

你的系统有 UWB 测距与 ESP-NOW 通信，天然具备"距离 + 邻居状态"两类观测。这一章的五篇论文正好覆盖：UWB 多机定位全景（4.1）、距离+运动模型的协同相对定位（4.2）、大规模集群的分簇定位（4.3）、时间同步与相对定位联合估计（4.4）、轻量嵌入式实现（4.5）。

## 4.1 UWB 多无人机与异构多机器人定位综述（2020）

**链接**：https://doi.org/10.1016/j.procs.2020.07.051

**做了什么**：首篇聚焦多无人机与异构多机器人系统的 UWB 定位综述，覆盖：支持自组网与动态部署的方法、协同定位技术、协同感知与协同机动（如无人机在移动平台上降落），并整理数据集，讨论 GNSS 拒止环境下的应用潜力。

**重点分析**：读这篇是为了选**测距体制**：双向测距（TWR）精度高但占用时隙，TDOA 需要时钟同步但可扩展，RSSI 只适合粗定位。对模块化无人机，模块数少（个位数到十几）时 TWR 更简单；模块数增加后要转向调度式 TWR 或 TDOA。综述里"自组网与动态部署"的部分与你们"模块可增减"的形态直接相关。

**可参考点**：
- 先定义测距更新率目标（例如每模块 10–50 Hz），再选体制与时隙分配。
- 无基础设施的相对定位（anchor-free）是可行路线，不依赖地面锚点。
- 综述的数据集可用于离线验证定位算法。

## 4.2 UWB 测距下的 MAV 集群协同相对定位（2024）

**链接**：https://arxiv.org/abs/2405.18234

**做了什么**：基于 UWB 的点对点测距，提出协同相对定位（CRL）：把每个"主机-邻居"对的相对运动动力学并入统一动态模型，把邻居之间的距离作为"额外信息"；用微分几何做可观测性分析，证明相比只用主机-邻居直接距离，可观测子空间更大；用对数-versal（LV）核的核化 EKF 处理重尾 UWB 噪声，并给出不动点迭代收敛条件与蒙特卡洛对比。

**重点分析**：这篇回答了一个关键问题：**只有距离、没有方位时，相对定位是否可观测**。结论是：把邻居间距离也纳入、并融合相对运动模型，可观测性更好。对你们，ESP-NOW 广播的邻居速度/高度/航向正好提供运动模型，UWB 提供距离，两者融合是自然路径。LV 核处理 UWB 的离群值（多径、非视距）也值得借鉴。

**可参考点**：
- 状态量取"相对位置 + 相对速度"，用邻居广播的状态做预测、UWB 距离做更新。
- 用鲁棒核（LV 或 Huber）抑制 UWB 离群值。
- 先做可观测性分析，再决定需要几组测距、什么几何构型。

## 4.3 GNSS 拒止下的无人机集群相对定位（2025）

**链接**：https://arxiv.org/abs/2509.04412

**做了什么**：针对大规模集群中丢包与计算复杂度导致定位误差大的问题，提出分簇框架：用谱聚类把集群分成子簇，簇内用矩阵补全 + 多维标度（MDS）得到高精度相对坐标，再通过簇间锚点融合生成全局地图；以 OTFS 的通信感知一体化（ISAC）为案例，同时做测距与通信，实验显示降低了大规模集群的定位误差与测距信息丢失的影响。

**重点分析**：模块数增加后，全连接测距的时隙需求是平方级增长，分簇是必然。对你的系统，短期内模块数少，不必分簇；但如果做"模块可扩展"，这篇提供了从局部坐标到全局坐标的路径。另一个启示是**通信信号本身可用于测距**（ISAC），这与"ESP-NOW 无测距"形成对比：若未来换用支持信道状态信息的链路，可省掉一部分 UWB。

**可参考点**：
- 模块数超过阈值时按几何/通信分簇，簇内高精度、簇间锚点融合。
- 用矩阵补全处理测距缺失（遮挡、非视距）。
- 评估"通信+测距一体化"的长期收益。

## 4.4 多机器人时间同步与相互定位联合估计（2023）

**链接**：https://arxiv.org/abs/2311.02948

**做了什么**：指出相对位姿估计中时间同步常被忽视，提出把时间偏移与相对位姿联合估计：在短时恒速假设下，把时间偏移估计与基于方位的相互定位用一个新误差表示融合，形成联合优化问题，用半正定松弛（SDR）得到无损松弛；再给出由粗到细的迭代方法扩展时间偏移的适用范围，仿真与实机验证时间同步对定位精度的显著收益。

**重点分析**：**时间偏移会直接变成距离误差**（距离 = 光速 × 时间）。UWB 的 TWR 对时钟要求相对低，但 TDOA 或"测距 + 状态广播"的融合对时间戳一致性敏感。ESP-NOW 没有硬件时间同步，如果你想做时隙化或基于时间戳的预测，就必须自己估计时钟偏移。这篇的联合估计框架可以借鉴：把时钟偏移作为状态量，与相对位置一起估。

**可参考点**：
- 每条消息带发送时间戳，接收端估计时钟偏移与漂移。
- 把时钟偏移纳入 EKF 状态，而不是假设同步。
- 时间同步精度直接决定"状态预测-测距更新"的融合权重。

## 4.5 轻量空中集群的机载测距相对定位与稳定性（2020）

**链接**：https://arxiv.org/abs/2003.05853

**做了什么**：为无基础设施的轻量空中集群提出相对定位：融合 UWB 测距与邻居共享状态（速度、偏航角速率、高度）；在 13 台 33 g、168 MHz MCU + 192 KB 内存的无人机上实现完全自主、快速、准确的相对定位，作者报告 16 Hz 下 13 架无人机的位置误差小于 0.2 m；并发现一个反直觉结论：状态漂移会导致控制动作、进而使系统重新可观测，因此不可观测性不构成问题。

**重点分析**：这篇证明了**在 MCU 级算力上做协同相对定位是可行的**，这对 ESP32-S3 很关键。它的"共享状态 + 测距"融合结构与你的系统几乎同构。另一个值得记住的观点：闭环控制会"激活"可观测性，不必追求离线可观测；但这是有条件的，不能作为设计保证。

**可参考点**：
- 在 MCU 上做 EKF 时优先融合"邻居共享状态 + 测距"，避免高维优化。
- 用 16 Hz 级更新率作为起点，实测计算与通信开销。
- 把"闭环可观测"作为工程直觉，但保留可观测性检查。

## 本章综合

| 问题 | 做法 | 依据 |
| --- | --- | --- |
| 相对定位是否可观测 | 融合邻居运动模型 + 邻居间距离 | 4.2 |
| UWB 离群值 | 鲁棒核（LV/Huber）、鲁棒 EKF | 4.2 |
| 模块数扩展 | 分簇 + 簇内 MDS + 簇间锚点融合 | 4.3 |
| 时间偏移 | 与相对位姿联合估计，时钟偏移入状态 | 4.4 |
| 嵌入式实现 | 共享状态 + 测距的低维 EKF | 4.5 |

**与你的系统映射（推断）**：

1. 观测源：UWB 距离（每对邻居）、ESP-NOW 邻居状态（速度、高度、航向、时间戳）、IMU（自身运动）。三者融合成一个相对位置 EKF。
2. 时间同步：ESP-NOW 无硬件同步，先用"消息时间戳 + 偏移估计"（4.4），精度不足时再考虑 UWB 辅助同步。
3. 扩展路径：当前模块数少，全连接 TWR 可行；模块数增加后按 4.3 分簇。
4. 风险：UWB 非视距与多径在机体遮挡、货物遮挡下会恶化；需要用鲁棒核与故障检测（见 06）。

**边界**：4.2/4.3/4.4 的观测模型假设与你的单旋翼倾转模块不同（模块姿态变化更剧烈），相对运动模型需要替换；4.5 的 33 g 平台算力低于 ESP32-S3，但其融合结构仍适用。
