# 09 开放问题与研究路线

> 本章不是论文综述，是把前面 8 章的空洞拼成一张问题地图，并给出一条可执行的验证路线。带"推断"的段落是本仓库的分析，不是文献结论。

## 9.1 文献没有直接回答的问题

### 1）单旋翼倾转模块的可行力旋量与饱和分配

现有模块化飞行器工作几乎都以四旋翼为模块（MARS、H-ModQuad、UFO），其可行力旋量多面体近似常值；单旋翼倾转模块的推力方向随倾转角连续变化，可行集合是"构型 + 倾转角"的函数。**直接用四旋翼的分配矩阵会在倾转饱和或大姿态时失效**。

可做：离线计算不同构型/倾转角下的力旋量多面体，在线用查表 + 小规模 QP；把"分配不可行"作为一等错误上报，而不是静默饱和。

### 2）测力计驱动的隐式协调（刚性绑缚）

GPAC 与桌面力学的工作用缆绳张力做局部载荷估计，刚性绑缚下内力分配更复杂：绑缚点力不仅反映载荷份额，还包含结构内力与装配应力。**如何从测力计读数中分离"载荷份额"与"内力"**，文献没有直接答案。

可做：先做静态标定（地面加载）建立"力读数 → 载荷/内力"的映射；飞行中用残差检测异常；分配器显式加入内力代价项（参考 2.9 的抓取矩阵框架）。

### 3）ESP-NOW 无时间同步下的协同控制

时间同步与相对定位联合估计（4.4）提供了框架，但没有针对 ESP-NOW 这类"无硬件时间戳、广播为主"链路的实现与误差分析。时钟偏移会直接进入基于时间戳的状态预测，进而影响编队。

可做：在消息层做时间戳与偏移估计；对比"不估计时钟"与"估计时钟"两种情况下的编队误差；把时钟偏移作为 EKF 状态。

### 4）通信-控制联合设计的数据年龄指标

3.4 提出用"数据年龄"而非丢包率衡量实时性；但如何把数据年龄纳入协同控制器设计（例如按年龄调整增益/预测步长），在多旋翼协同搬运里还没有系统结果。

可做：记录每条状态消息的年龄，控制器按年龄降权；用"年龄超过阈值 → 切本地保持"的策略。

### 5）重构中间态的可控性（单旋翼）

1.3/1.4 给出了四旋翼 MARS 的重构序列规划；单旋翼模块在"部分绑缚、部分自由"的中间态，推力方向与结构约束都不同，**最小可控装配体的判据需要重做**。

可做：把中间态建模成"混合构型"，用 07 章的可行力旋量方法逐态校验；重构序列规划器把"中间态可控性裕度"作为硬约束。

### 6）故障检测与重构决策的闭环

现有工作要么做故障检测、要么做重构规划，**把"检测 → 决策（降级/重构/降落）→ 执行"做成闭环**的模块化飞行器工作很少。测力计提供了额外残差通道（6 章），但如何设定阈值、如何避免误报，缺少公开方法。

可做：多源残差（姿态、位置、UWB、测力计）做融合检测；决策用状态机 + 风险代价；把"误报/漏报"纳入实验指标。

### 7）大规模异构模块的分布式优化

5.7 的 C-ADMM 与 5.4 的嵌入式 DMPC 展示了可行性，但 ESP32-S3 级算力、ESP-NOW 级带宽下的收敛速度与稳定性还没有公开结果。

可做：先仿真不同模块数/带宽/迭代次数下的收敛；再在 2–4 个模块上做硬件在环。

### 8）标准化基准与安全认证

8.1 是系统对比，但没有统一的任务基准（负载形状、故障注入、通信降级标准）。这让不同论文的数字难以横向比较，也让"安全认证"无从谈起。

可做：定义你们的基准任务（例如"2 kg 矩形负载、4 模块、5 m 悬停、单模块失效"），固定指标与记录方式，便于纵向对比自己的迭代。

## 9.2 建议的验证路线（推断）

| 阶段 | 目标 | 关键验证 | 对应章节 |
| --- | --- | --- | --- |
| P0 单模块 | 推力/倾转/测力/UWB/ESP-NOW 标定 | 台架 + 单机悬停，建立传感器噪声模型 | 03、04、07 |
| P1 双模块刚性连接 | 相对定位 + 内力 + 分配 | 悬停时两模块的相对位置误差、绑缚点力一致性 | 02、04、07 |
| P2 多模块 + 货物 | 协同搬运 | 轨迹跟踪、载荷份额估计、通信降级实验 | 02、03、05 |
| P3 故障与重构 | 单模块失效、断连 | 恢复时间、任务完成率、是否触发重构 | 01、06 |
| P4 泛化 | 不同货物/构型/模块数 | 构型自辨识、分配矩阵自动重建 | 01、05、07 |

## 9.3 如果只读三篇

- 想直接做系统：**2.1 Oishi 单旋翼协同搬运**（最接近你的硬件形态）。
- 想降低通信依赖：**2.6 GPAC**（本地力估计 + 隐式协调）。
- 想把整机当一架飞机控：**1.1 MARS-Dragonfly**（虚拟力旋量 + 两阶段分配）。
