# 15 判别实验协议（D1–D3）

> 这一章把 [14 章](14_feasibility_budget.md) 的三个判别实验写成可执行的协议：设备、接线、标定、测试矩阵、数据格式、判定阈值、分析脚本。目标不是"做完实验再想怎么分析"，而是**先固定判据再采数**，避免看完结果再改标准。所有阈值在采数前登记；改阈值必须记录原因。

## 15.1 原则

1. **判定先行**：每个实验的通过标准在 15.3–15.5 中给出，采数前打印一份贴在现场。
2. **数据可复算**：原始数据落 JSON，分析脚本从原始数据重算指标，不允许手抄数字。
3. **失败也算结果**：D2 不通过同样决定主线选择（14.7），不是"实验失败要重做"。
4. **单变量**：D1 只动发送频率；D2 只动故障幅值与通信周期；D3 只动连接刚度。每轮改动记录到 `runs/README`。

## 15.2 台架与工具

| 项 | 用途 | 备注 |
| --- | --- | --- |
| 4 × ESP32-S3 XIAO | D1 通信节点 | 与模块同型号；固件用 ESP-IDF v5.x |
| Wi-Fi 抓包（可选） | 核对空口帧长/速率 | 802.11 监听模式；没有也能做 |
| 双模块刚性台架 | D2/D3 | 两模块背对背固定，绑缚点装测力计 |
| 六维力台或双测力计 | D2 合力/内力 | 采样 ≥200 Hz，量程覆盖 2 倍单模块推力 |
| 砝码组 0.5/1.0/1.5 kg | D3 载荷 | 精度 ±1 g |
| 刚性杆 + 弹簧（k 已知） | D3 连接刚度对比 | 弹簧刚度用砝码标定 |
| 直流电源 + 电流探头 | 推力标定交叉验证 | 推力 ≈ 电流模型，仅作旁证 |

**推力标定**：单模块固定在测力台上，油门 0–100% 扫 21 点，每点停 5 s 取均值；得到 `thrust = a·pwm² + b·pwm + c`（或查表）。后续所有"10% 推力"都按标定曲线换算，不用百分比猜。

## 15.3 D1：带宽、丢包与数据年龄

### 15.3.1 固件与帧

- ESP-NOW 广播模式，固定信道 6，关闭长距离模式；应用层 CRC16。
- 帧载荷 120 B：`seq(4) + sender_id(1) + tx_us(8) + 填充(107)`；填充内容用递增序列，便于发现截断。
- 接收端记录：`rx_seq, sender, rx_us, rssi`，通过 USB 串口以 460800 bps 输出 JSON Lines。
- **时延测量用回声**：接收端回发含原 `seq` 的 20 B 回声帧；发送端算 `RTT/2`。ESP32 之间没有硬件时钟同步，单向延迟不可直接测，`RTT/2` 是唯一诚实的近似。

### 15.3.2 测试矩阵

| 频率 | 时长 | 重复 | 说明 |
| --- | --- | --- | --- |
| 10 Hz | 10 min | 3 | 低负载基线 |
| 20 Hz | 10 min | 3 | 目标工作点 |
| 50 Hz | 10 min | 3 | 边界点 |
| 100 Hz | 10 min | 3 | 预期饱和点 |

顺序随机化（用随机数决定当天顺序），每轮之间停 1 min 让射频/温度恢复。

### 15.3.3 指标与判定

- 接收率 = 收到帧数 / 发送帧数（按 `seq` 去重后计）。
- 数据年龄 = 发送端测量时刻到接收端可用时刻：`RTT/2 + 发送排队`；采样时刻记录在 `tx_us`。
- 判定（预注册）：
  - **20 Hz：接收率 ≥ 99%，RTT/2 P95 ≤ 10 ms，数据年龄 P95 ≤ 35 ms → 通过**。
  - 50 Hz：接收率 ≥ 95%，RTT/2 P95 ≤ 15 ms → 通过（作为边界证据）。
  - 100 Hz：预期不通过；若接收率 < 90%，记录为"饱和证据"，用于论文中的占空比论证。

## 15.4 D2：力残差检测延迟

### 15.4.1 台架与扰动注入

- 双模块背对背刚性连接，整体固定在六维力台上；两模块各自推力指令由飞控测试模式给出。
- 标定：先用 15.2 的推力曲线确认两模块在 50% 油门时推力差 <2%；否则先配平。
- 扰动：
  - **推力阶跃**：单模块指令从 50% 阶跃到 55%（10% 相对变化），上升时间 <10 ms，持续 2 s，重复 20 次；
  - **载荷突变**：在力台上挂/脱 0.2 kg 砝码（等效约 5% 总推力），重复 20 次。
- 同步记录：力台原始数据（≥200 Hz）、通信日志（20/50/100 Hz 各一组）、PWM 指令。

### 15.4.2 检测器（预注册）

- 残差 `r_k = 合力_k − 标称合力`（标称由标定曲线与指令算出）。
- CUSUM：`S_k = max(0, S_{k−1} + r_k − ν)`，`ν = 0.5σ`，报警阈值 `h` 由 15.4.3 选定。
- 检测时间 = 首次报警的样本序号 × 样本周期；未报警按 2 s 截断。

### 15.4.3 阈值预研（先算清误报代价）

用固定种子的蒙特卡洛算 CUSUM 的平均运行长度 `ARL₀` 与检测延迟（`ν=0.5σ`，2000 次重复）：

| 阈值 h | ARL₀（中位，样本） | 20 Hz 下 10 min 期望误报 | SNR=10 延迟 | SNR=5 延迟 | SNR=3 延迟 |
| --- | --- | --- | --- | --- | --- |
| 5.0 | 974 | 12.3 次 | 1 样本 | 2 样本 | 3 样本 |
| 6.0 | 2510 | 4.8 次 | — | — | — |
| 7.0 | 6850 | 1.8 次 | — | — | — |
| 8.0 | 18792 | **0.6 次** | **1 样本** | 2 样本 | 4 样本 |
| 9.0 | ≥200000 | ≤0.1 次 | — | — | — |

**取 h=8**：10 分钟误报 0.6 次可接受，SNR≥5 时延迟 ≤2 样本。

### 15.4.4 判定（预注册）

- 20 Hz 通信、10% 推力阶跃：**检测时间中位数 < 150 ms，且 10 min 空载基线误报 < 1 次 → 通过**。
- 50 Hz/100 Hz 组只做对照，不参与判定。
- **同时记录 σ**（空载 60 s 残差标准差，占单模块推力百分比）。σ 决定 SNR：SNR = 10% / σ。若 σ > 2%（SNR < 5），按 14.7 判定 D2 不通过，进入"多测点联合 CUSUM"备选方案。

### 15.4.5 预研结论：150 ms 的预算只剩 3 个样本

20 Hz 下 150 ms = 3 个样本。h=8 时 CUSUM 占 1–2 个样本，**三点滑动平均再占 1 个样本（群延迟）**，合计 2–3 个样本，正好压线。因此故障检测路径**不能**再用多点滤波：力控制环可以用滤波后的力，故障检测必须用原始残差并行运行。这一条要在固件里就分开，不能事后补。

多测点联合可把独立噪声的 SNR 提高约 √12 ≈ 3.5 倍，但结构传导的振动噪声是相关的，实际增益要用 D2 的 12 通道数据测相关矩阵后再定——这是 D2 的第二个产出。对**单模块掉推力**，四路平均反而把 SNR 砍半（信号 ÷4、独立噪声只 ÷2），正确形态是并行 CUSUM + OR + 力台仲裁，数值见 [16 章](16_force_residual_sim.md)。

## 15.5 D3：刚性 vs 柔性绑缚

### 15.5.1 台架与工况

- 两模块刚性连接（钢杆）或柔性连接（弹簧，k 用砝码标定）。
- 载荷：0 / 0.5 / 1.0 / 1.5 kg，静态悬挂在连接件中点。
- 每个（连接方式 × 载荷）组合重复装夹 20 次；每次装夹后静置 30 s 再采样 10 s。

### 15.5.2 指标

- **重复性**：同一工况 20 次装夹下，测力向量均值与标准差；变异系数 CV = σ/|μ|。
- **内力指标**：两测点力的垂直载荷方向分量之差 `⊥ = |(f₁ − f₂) − proj_载荷(f₁ − f₂)| / |W|`；刚性连接下预紧/装配应力会留下非零 `⊥`，柔性连接会松弛到接近零。
- **载荷份额误差**：`|f₁ + f₂ − W| / |W|`。

### 15.5.3 判定（预注册）

- 刚性工况的 `⊥` 中位数 ≥ 柔性工况的 3 倍，且两者 95% 置信区间不重叠 → 通过。
- 刚性工况重复装夹 CV < 10% → 通过（否则内力的"可重复测量"不成立，A 主线按 14.7 收窄）。
- 若两种工况 `⊥` 都接近零：说明当前绑缚刚度不足以产生可测内力，D3 结论为"该指标不可用"，需改用应变片或提高预紧。

## 15.6 数据格式与命名

原始数据一律 JSON Lines，一行一个样本：

```json
{"exp":"D2","run":"D2_20261020_20Hz_r1","t_us":1234567,"module":1,
 "mode":"thrust_step","cmd_pwm":0.55,"f":[0.0,0.0,9.81],
 "tx_seq":42,"rx_seq":41,"note":""}
```

文件命名：`runs/<exp>_<YYYYMMDD>_<cond>_r<k>.jsonl`；同目录 `meta.json` 记录台架照片编号、标定曲线、固件版本、随机化顺序。`runs/` 不入库（体积与可重新生成），只提交分析报告 JSON 与图。

## 15.7 分析脚本（stdlib，可直接跑）

D2 的检测延迟与误报（把 15.4.3 的预研脚本参数化成数据驱动）：

```python
import json, statistics

def load(path):
    rows = [json.loads(l) for l in open(path, encoding="utf-8") if l.strip()]
    rows.sort(key=lambda r: r["t_us"])
    return rows

def residual(rows, nominal):
    return [r["f"][2] - nominal for r in rows]  # 竖向合力示例

def cusum_delay(res, nu, h):
    s = 0.0
    for k, r in enumerate(res, 1):
        s = max(0.0, s + r - nu)
        if s > h:
            return k
    return None

rows = load("runs/D2_20261020_20Hz_r1.jsonl")
res = residual(rows, nominal=0.0)          # nominal 由标定曲线算，示例取 0
sigma = statistics.pstdev(res[:1200])      # 空载 60 s
fault = 0.10 * module_thrust               # 由 15.2 的推力标定换算，单位与 f 一致
print("sigma =", sigma, "SNR =", fault / sigma if sigma else None)
print("detect_samples =", cusum_delay(res, nu=0.5*sigma, h=8*sigma))
```

D1 的接收率与年龄：按 `seq` 去重、`RTT/2` 取 P50/P95；D3 的 CV 与 `⊥` 用 `statistics` 直接算。三段脚本都只依赖标准库，避免给台架电脑装环境。

## 15.8 风险与替代路径

| 风险 | 触发信号 | 替代方案 |
| --- | --- | --- |
| ESP-NOW 实测吞吐低于 100 kbps | D1 20 Hz 接收率 <99% | 降频到 10 Hz；改事件触发 + 稀疏拓扑（候选 D） |
| 力噪声 σ >2% 推力 | D2 空载残差大 | 多测点联合 CUSUM；加隔振；故障检测改用电流残差（电调电流对推力更直接） |
| 刚性连接不产生可测内力 | D3 `⊥` 两工况无差异 | 提高预紧、换应变片；A 主线删除内力抑制 |
| 台架无法闭环 | 只能静态加载 | D2 退化为"静态阶跃 + 开环"，仍可测检测延迟；动态闭环留到飞行阶段 |

## 15.9 结果如何回填

D1–D3 的原始数据、σ、ARL₀、检测延迟、`⊥` 全部回填 14.2 参数表与 14.7 决策表；14 章的预算脚本重跑一遍，论文里的每个数字都能对应到 `runs/` 下的一份 JSON 和一条命令。**在回填之前，14 章的"假设/待实测"标记不得删除。**
