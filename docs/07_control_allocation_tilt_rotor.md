# 07 控制分配与倾斜旋翼

> 本章回答：整机想要一个合力与合力矩，怎么分给每个模块的推力与倾转角；推力饱和、倾转速率、模块间气动干扰怎么进约束；为什么不能直接用伪逆。

你的单旋翼倾转模块有一个特殊性：**单个模块的推力方向随倾转角变化**，因此"分配"不是线性的。本章两篇论文分别处理两个核心问题：一般过驱动平台的分配优化（7.1），以及模块靠得很近时的下洗干扰（7.2）。

## 7.1 MOMAV：高对称全驱动多旋翼的优化分配（2025）

**链接**：https://arxiv.org/abs/2506.08868

**做了什么**：设计 MOMAV：六条旋翼臂指向八面体顶点、每条臂可绕长轴主动旋转，使飞行器全驱动且高对称（飞行效率基本不随姿态变化）；给出带滑环的旋转臂结构，以及基于序列二次规划（SQP）的控制分配算法，在线计算油门与臂角设定值。作者报告位置/姿态扫描测试的平均误差约 6.6 mm / 2.1°，姿态扫描约 11.8 mm / 3.3°。

**重点分析**：这篇把分配写成**非线性约束优化**：决策变量是推力与臂角（对你的系统是推力与倾转角），约束是推力上下限、倾转速率、期望力旋量。SQP 能处理非线性，但计算量比 QP 大。对你的 ESP32-S3，直接跑 SQP 不现实；可借鉴的是"把分配分成离线可行域 + 在线 QP"：离线算好不同倾转角下的可行力旋量多面体，在线只解小规模 QP。

**可参考点**：
- 分配变量选"推力 + 倾转角"，约束含速率与饱和。
- 离线建可行力旋量多面体，在线查表 + QP。
- 对称设计能降低分配问题条件数，硬件设计阶段就考虑。

## 7.2 考虑下洗的过驱动平台控制分配（2022）

**链接**：https://arxiv.org/abs/2207.09645

**做了什么**：过驱动多旋翼可以独立控制位置与姿态，但靠得很近的推力单元会产生下洗干扰，互相抵消推力、威胁稳定；作者提出考虑下洗效应的控制分配框架，在硬件约束下探索整个分配空间求最优解，兼顾避免下洗与推力效率，并在不同硬件配置上仿真与实验验证。

**重点分析**：模块化无人机把多个推力单元装得很近，**下洗是必然问题**，而且会随构型、倾转角、间距变化。这篇的价值是把"气动干扰"变成分配约束/代价项，而不是事后靠调参。你们的测力计可能也能观测到部分干扰（绑缚点力异常），可作为在线辨识的输入。

**可参考点**：
- 在分配代价里加入"下洗风险"项（间距小、推力大时惩罚）。
- 用实验/CFD 建立间距-推力损失的经验模型，作为约束。
- 构型设计阶段就把最小间距作为约束。

## 本章综合

**分配问题的一般形式（推断）**：

```
minimize    ||W·(B(θ)·u - w_des)||² + λ·J_energy + μ·J_downwash
subject to  u_min ≤ u ≤ u_max
            θ_min ≤ θ ≤ θ_max,  |θ̇| ≤ θ̇_max
            B(θ)·u ∈ W_feasible
```

其中 `u` 是推力，`θ` 是倾转角，`B(θ)` 把模块推力映射到整机力旋量，`W_feasible` 是可行力旋量集合。

| 取舍 | 建议 |
| --- | --- |
| 伪逆 vs QP | 伪逆忽略饱和，接近极限时会出错；用带约束 QP |
| 线性 vs 非线性 | 倾转角小范围变化可线性化；大范围或大倾转必须非线性 |
| 集中 vs 分布式 | 模块数少时集中 QP 足够；扩展时用 C-ADMM（见 5.7） |
| 下洗 | 作为约束或代价项，不要事后补偿 |

**与你的系统映射**：单旋翼倾转模块的 `B(θ)` 是非线性的，且每个模块的倾转机构有速率限制。建议先在 MATLAB/Python 里画出"给定构型下的可行力旋量多面体"，再决定控制器能要求多大的加速度/角加速度；这一步做错，飞控会持续在饱和边缘，表现为姿态振荡与电机过热。
