# 21 数据回填手册：从协议到可投稿的数字

> [14](14_feasibility_budget.md)–[20](20_internal_force_identifiability.md) 里的数字分三类：**文献事实**（可引用）、**计算结论**（脚本可复现，但输入是假设）、**待实测**（D1–D3 才能定）。本章把第三类逐条落到字段与文件上——做完 D1–D3 后，照这一章回填，论文里的每个数都能追到 `runs/` 里的一个 JSON。
>
> 这不是又一份协议；它是**回填合同**：哪个字段、填到哪张表、改哪条判据、失败时怎么记。

## 21.1 三条规则

1. **一个数只写一次**：参数第一次出现的表格是"主表"（14.2 平台参数、14.7 决策表、15.5 判据、20.5 刚度），其它章引用主表，不复制值。
2. **回填不是改数字，是改状态**：`假设/待实测` 标记只有拿到 `runs/` 数据才删；删的时候在 `meta.json` 留证据（文件路径 + 命令）。
3. **失败也要回填**：D1/D2/D3 任一条不通过，把"不通过"的实测值写进主表并翻转 14.7 的决策——**不允许把不通过的数据留在 `runs/` 里、正文继续用假设值**。

## 21.3 `runs/` 的目录合同

```
runs/
├── meta.json                     # 全局：日期、台架照片、固件、随机化顺序、k 标定
├── D1_20261022_20Hz_r1.jsonl
├── D1_20261022_20Hz_r1.meta.json # 单次运行：频率、帧长、丢包、年龄
├── D2_20261023_step_r1.jsonl
├── D2_20261023_step_r1.meta.json
├── D3_20261024_rigid_1kg_r1.jsonl
└── D3_20261024_rigid_1kg_r1.meta.json
```

全局 `meta.json` 至少含：

```json
{
  "date": "2026-10-22",
  "bench_photo_ids": ["P-001", "P-002"],
  "firmware": "esp32s3-xiao-0.3.1",
  "randomization": "seeded-20261019",
  "d3": {"k_N_per_m": 95000, "k_method": "direct",
         "clamp_repeat_um": 20, "alpha_1_K": 2.3e-5,
         "temp_sensor": "DS18B20"},
  "d1": {"frame_bytes": 120, "channel": 6}
}
```

**规则**：`runs/` 不进 Git（体积 + 可重生成）；提交的是"回填后的 JSON 报告 + 图"，并在报告里写清生成命令。校验脚本 `experiments/validate_runs.py` 会检查字段齐不齐、单次运行有没有 `meta`，缺字段直接非零退出。

## 21.5 回填顺序（建议 7 步）

1. D1 先跑：吞吐/丢包/年龄决定后面还能不能按 20 Hz 做。
2. D3 的 `k` 与装夹重复性：决定内力指标是否可用；`k` 同时是 20 章的输入。
3. D2：σ、检测延迟、误报；σ 决定检测节拍（25/26.7/50 Hz）。
4. 改主表：14.2 参数表逐行替换"假设"值。
5. 重算 14.7 决策表：D1+D2 过 → A；D1 只在 10 Hz 成立或 D2 不过 → B；D3 重复性差 → A 删内力抑制。
6. 更新 15.5/20.7 的"待实测"标记与 17.8 证据审计状态。
7. 提交回填报告 JSON + 图，并在 README"证据与可信度"里改日期与"实测"字样。

## 21.9 局限

- 本章是**合同**，不是结果：字段齐不齐不等于数据可信；D1–D3 的协议偏差（台架、标定、随机化）仍按 15 章判断。
- 字段名以 `runs/` 实际数据为准；若台架改了量程/采样率，先改本表再跑，避免"数据迁就文档"。
- 未覆盖飞行实验：室外飞行的风、温、振动会引入 20 章没建模的扰动；飞行数据回填另开一章，不混进 D1–D3。
