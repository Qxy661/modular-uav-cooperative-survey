# 08 系统集成、仿真与评测

> 本章回答：别人怎么搭系统、怎么做实验、怎么证明"协同真的比单机强"；以及为什么通信模型必须在仿真里建模，否则 sim-to-real 会骗你。

## 8.1 实时可实现的协同空中操作系统对比研究（2024）

**链接**：https://arxiv.org/abs/2403.14347

**做了什么**：聚焦四旋翼/多旋翼协同空中操作的综述：比较在真实环境中实时实现并测试过的原型系统，讨论其建模与控制方法、适用场景与可实现性，总结挑战，并给出"按功能/操作性/应用域选择下一代原型"的指南。

**重点分析**：这篇是**系统选型清单**：多机协同操作有哪几种拓扑（刚性抓取、缆绳、工具）、各自需要什么感知与控制、实验规模多大。写你们的系统设计文档时，可以用它的维度（机械连接方式、控制架构、感知配置、实验条件）做对照，避免"只做算法不做系统"。

**可参考点**：
- 用统一维度对比自己的工作与已有原型（连接方式、模块数、负载、通信、控制频率）。
- 实验至少报告：负载/模块数、跟踪误差、故障场景、通信条件。
- 注意"实时可实现"这一筛选条件：很多论文的算法跑不动在机载。

## 8.2 BotNet：精确通信模型对集群控制影响的仿真器（2021）

**链接**：https://arxiv.org/abs/2108.13606

**做了什么**：指出现有集群仿真器多用简单传播模型、无法反映真实射频网络；提出开源仿真器 BotNet，内嵌符合标准的 6TiSCH 时间同步信道跳频 mesh 网络仿真器；用 10 到 2500 个智能体实验表明，更准确的通信模型会显著限制 flocking 与编队控制的表现，进而提出应修改现有传播模型以缩小 sim-to-real 差距。

**重点分析**：这篇的结论对你们是警告：**在理想通信假设下调好的编队控制器，上真机可能完全不工作**。ESP-NOW 的丢包、时延、广播冲突在仿真里必须建模，否则实验会反复"仿真好好的，一飞就散"。

**可参考点**：
- 仿真中加入：丢包率、时延分布、广播冲突、节点数影响。
- 用实测的 P50/P99 时延与丢包率标定仿真参数。
- 把"通信降级"作为标准测试场景（丢 20%、时延加倍、单模块断连）。

## 本章综合：评测清单（推断）

| 维度 | 建议指标 | 说明 |
| --- | --- | --- |
| 跟踪性能 | 位置/姿态 RMSE、最大误差 | 分悬停、轨迹、扰动三档 |
| 协同质量 | 模块间相对位置误差、内力/力分配偏差 | 体现"是不是真的协同" |
| 通信 | P50/P99 时延、丢包率、数据年龄 | 必须与飞行数据同步记录 |
| 容错 | 故障后恢复时间、任务完成率、性能下降 | 单模块失效、断连、UWB 遮挡 |
| 能耗 | 每模块电流/推力、续航 | 分配算法的实际收益 |
| 可扩展性 | 模块数 2/4/6/8 的表现曲线 | 验证"模块化"是否成立 |

**实验设计建议**：
1. 先做**单模块 + 地面台架**：标定推力-倾转角-力、测力计、UWB 测距噪声。
2. 再做**双模块刚性连接**：验证相对定位、内力、分配。
3. 然后**多模块 + 货物**：逐步加模块数，记录通信与定位退化。
4. 最后**故障注入**：拔一个模块、遮挡 UWB、限制 ESP-NOW 带宽。

**边界**：8.1 是综述，不给代码；8.2 的 6TiSCH 模型与 ESP-NOW 不同，不能直接复用其参数，但"通信模型影响控制结论"这一方法论成立。
