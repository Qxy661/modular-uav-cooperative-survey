# 07 容错、重构与韧性

> RQ6：模块化系统的故障有哪些类型？如何检测、决策与执行？重构的中间态为什么危险？

## 7.1 问题定义

模块化相对一体化的核心卖点是**故障后可重构**。但要把它变成可交付能力，需要三件事同时成立：

1. **可检测**：故障有可观测信号（姿态/位置残差、力残差、通信心跳、电流/转速）。
2. **可决策**：降级、重构还是降落？决策要基于剩余可控性与任务价值。
3. **可执行**：重构序列的每个中间态都稳定可控。

文献对三件事的覆盖并不均衡：重构规划较多（[5][6][7]），检测与决策闭环较少，韧性度量多为框架（[34]）。

## 7.2 方法族与代表工作

- **韧性框架**：[34] 区分鲁棒性与韧性，给出"感知/控制/规划/学习"四层韧性手段分类，强调韧性要可度量（恢复时间、性能损失、任务完成率）。
- **容错控制重分配**：[5] 按模块相对质心的力臂重新分配期望合力/力矩，适配任意模块数与装配构型。
- **重构规划**：[6] 以中间态可控性裕度约束拆装序列；[7] 扩到任意形状与多重故障，构造最小可控装配体。
- **失效下继续任务**：[11] 单旋翼团队在机器人失效下继续搬运；[15] 6 机在单机失效/断连下作者报告 94% 成功率。
- **通信故障下的容错编队**：[35] 用预设性能函数定义故障后的瞬态/稳态行为，处理执行器饱和；可把"恢复时间与误差界"写成可验收指标。

## 7.4 证据强度与局限

- 没有 A 级实证工作；重构与容错多为仿真（[5][6][7][35]），实机证据集中在"失效后继续飞"（[11][15]），而非"重构"。
- 检测环节普遍被简化：多数工作假设故障已被识别，真正做"检测 → 决策 → 执行"闭环的很少（10 章 G5）。
- 重构判据基于四旋翼模块，单旋翼模块的中间态可控性需要重做。

## 7.5 对目标系统的启示（推断）

1. **测力计是额外检测通道**：模块推力衰减会先体现在其承担的力份额下降，可能早于姿态误差暴露；可做力残差检测。
2. **故障谱要覆盖绑缚点**：绑带松动、单点失效在文献中很少讨论，但对"绑缚货物"系统是主要风险。
3. **韧性指标前置**：定义恢复时间、任务完成率、性能下降幅度，再设计控制器与实验。
4. **重构按中间态规划**：如果做"拆掉坏模块"，必须校验过渡结构可控（[6][7]），单旋翼模块需重新推导判据。

**本章结论**：容错控制与重构规划各自成熟，但"检测-决策-执行"闭环与"绑缚点故障"是明显空白；这也是 11 章候选 C 的立足点。
