# 18 数据年龄与协同环频率：ESP-NOW 排队模型

> 本章解决一个此前被含糊带过的数：14 章写"20 Hz 下数据年龄 P95 ≈ 30–35 ms"，17 章把它当作平台参数 P6。模型算下来，这个数只在一种定义下成立。**结论先行**：
>
> 1. "数据年龄"必须拆成**交付年龄**（生成 → 接收，P95 ≈ 8 ms）与**陈旧度**（控制层用的最新帧已经旧了多久，P95 ≈ 72 ms，约 1.4 个周期）；35 ms 既不是前者也不是后者；
> 2. 20 Hz 广播占空 31%，交付年龄很低，但陈旧度上限由采样周期决定——**要压低陈旧度只能提高频率，而 100 Hz 在 250 kbps 下排队发散**（10 min 积压约 322 s）；
> 3. 事件触发必须带心跳：50 Hz、触发概率 0.25 时，无心跳陈旧度 P95 ≈ 214 ms，心跳 5 个周期降到 ≈ 96 ms；20 Hz 下事件触发无法满足 150 ms 检测预算。

## 18.1 为什么必须拆成两个年龄

两个量回答不同的问题：

- **交付年龄**：这一帧在路上花了多久？决定排队、空口、处理是否超预算，是 D1 直接能测的。
- **陈旧度**：控制层此刻手里的最新一帧，距离它被生成过了多久？决定状态估计与故障检测看到的是"多旧的世界"。

对 20 Hz 采样，即使交付瞬间完成，控制层也不可能拿到"刚刚生成"的帧：它只能在周期边界取上一帧，相位等待平均 25 ms、最坏接近 50 ms。**陈旧度的下界由采样周期决定，与链路快慢无关**。14 章的 30–35 ms 实际混用了两个口径：半周期 25 ms + 处理 5–10 ms 是"典型陈旧度"，不是 P95；而 P95 要按相位均匀分布算，约 1.4 个周期。

## 18.2 模型

参数与 17.3 的 P1–P11 一致：

| 项 | 值 | 说明 |
| --- | --- | --- |
| 帧长（空中） | 120 B | P2，含 802.11 头 |
| 链路容量 | 250 kbps | P4 的乐观上界 |
| 单帧空口 | 3.84 ms | 120×8/250k |
| 模块数 | 4 | 共享一个广播信道，串行服务 |
| 生成抖动 | U[0, T) | 各模块相位独立 |
| 丢包 | 每帧独立 p_loss，不重传 | ESP-NOW 广播默认语义 |
| 处理 | 1 ms | 接收 + 解包 + 写共享内存 |
| 陈旧度采样 | 周期边界 u_m = mT | 控制层取"已到达的最新帧" |

交付年龄 $d_i = w_i + a + p$（排队等待 + 空口 + 处理）；陈旧度 $s_m = u_m - t_{\text{gen}}(\text{latest arrived})$。

**简化（写论文时要照抄这一条）**：不做碰撞建模，把信道当作时隙化串行服务；因此结果是**乐观下界**。真实 ESP-NOW 在 4 个发送端同周期广播时会有碰撞与退避，D1 实测只会更差。

## 18.3 结果

表 18-1 各频率与丢包下的交付年龄 / 陈旧度 / 占用（10 min，seed 20261019，N=4）：

| 频率 | 交付 P95（0 / 1% / 5% 丢包） | 陈旧度 P95（0 / 1% / 5%） | 占用 | 可行 |
| --- | --- | --- | --- | --- |
| 10 Hz | 7.2 / 7.1 / 7.1 ms | 99 / 100 / 146 ms | 15% | 是 |
| 20 Hz | 8.2 / 8.2 / 8.1 ms | 72 / 74 / 82 ms | 31% | 是 |
| 50 Hz | 11.5 / 11.5 / 11.2 ms | 36 / 37 / 38 ms | 77% | 是（余量小） |
| 100 Hz | 排队发散（P95 ≈ 305 s） | 随之发散（P95 ≈ 199 s） | 154% | **否** |

100 Hz 的交付年龄不是"更大"，而是**无界**：每周期 4 帧 × 3.84 ms = 15.36 ms，超过 10 ms 的周期，队列只进不出；10 min 后积压约 322 s（`last_finish_s`）。这从排队论上确认了 17.5 的 D4：100 Hz 只能作饱和对照，不能作为工作点。

表 18-2 事件触发（50 Hz，触发概率 q=0.25，丢包 1%）：

| 心跳间隔 | 交付 P95 | 陈旧度 P95 | 占用 |
| --- | --- | --- | --- |
| 无心跳 | 7.5 ms | **214 ms** | 19% |
| 5 周期 | 8.0 ms | **96 ms** | 19% |
| 10 周期 | 7.6 ms | **165 ms** | 19% |

占用从 77% 降到 19%，代价是陈旧度上升。**心跳是必须的**：没有心跳，一旦状态长时间不变化（悬停、匀速），接收端会拿着越来越旧的帧；10 周期心跳已超出 150 ms 检测预算，5 周期才落在预算内。

## 18.4 四个发现

1. **35 ms 是典型值，不是 P95**。交付 P95 只有约 8 ms；陈旧度 P95 约 72 ms。控制器时延裕度若按 35 ms 留，会在相位最坏时低估一倍。正确写法：交付年龄 P95 ≈ 8 ms，陈旧度 P95 ≈ 1.4T（20 Hz 下 ≈ 72 ms）。
2. **陈旧度的下界是采样周期，不是链路**。提高链路容量能把交付年龄压到接近 0，但压不住 1.4T；要降陈旧度只能提高频率——而 100 Hz 在当前容量下不可行。20–25 Hz 不是保守选择，是"容量可行 × 陈旧度可接受"的唯一交集。
3. **故障检测的 150 ms 预算要按样本域理解**。15.4.5 的"3 个样本"在 20 Hz 下是 150 ms，这是采样域；物理时间还要加上交付年龄（≈8 ms）与故障相位（≤1 周期）。论文里应写"3 个连续样本，对应物理时间约 160 ms（含交付）"，不要把两个口径混写。
4. **事件触发只在 50 Hz 起有意义**。20 Hz 下心跳 5 周期 = 250 ms，已超过检测预算；50 Hz + 心跳 5 周期 = 100 ms 上限，才既省带宽又不失控。这给 E3 的实验设计加了一条硬约束：事件触发必须与 50 Hz 标称周期一起测。

## 18.6 局限

- 无碰撞、无退避、无 ACK 重传；真实 ESP-NOW 的广播丢包与碰撞会让交付年龄更差，D1 会给出真实分布。
- 处理延迟固定 1 ms；实际取决于固件与共享内存实现。
- 事件触发的 q=0.25 是假设（14.2 的 25% 事件比例），不是实测。
- 陈旧度只按"周期边界取最新帧"算；若控制器改用预测/外推，有效陈旧度会低于此模型，但那是控制器设计，不是通信预算。
