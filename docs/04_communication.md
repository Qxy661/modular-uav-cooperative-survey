# 04 模块间通信与网络化控制

> RQ3：低带宽、无时间同步、广播为主的模块间链路，如何与协同控制器一起设计？

## 4.1 问题定义

模块间通信不是"把状态发出去"这么简单。对控制而言，真正进入闭环的是四个量：**采样周期、端到端时延、丢包率、数据新鲜度（age of information）**。WNCS 综述 [18] 把它们称为通信与控制的"关键交互变量"，并指出联合设计优于分别优化。

模块化飞行器的特殊约束：
- 通信拓扑随模块增减、遮挡、丢包而变化（切换拓扑）；
- 控制环频率可能高于链路可靠更新率；
- 没有硬件时间同步时，"状态"与"时间戳"不一致会直接变成控制误差。

## 4.2 方法族与代表工作

- **通信-控制联合设计**：[18] 系统梳理协议各层参数如何影响时延/丢包分布，以及控制器如何把这些变量纳入设计；这是本章的理论框架。
- **服务质量与抖动控制**：[19] 分析无线 ROS 的 TCP 在带宽、时延、抖动上的问题，用多 core + 流优先级降低时延与抖动。启示是**抖动比平均时延更伤控制**。
- **广播/并发传输**：[20] 用并发传输替代异步逐点发送，5 台异构机器人实现厘米级空间与毫秒级时间精度、低占空比。对"所有人需要同一份状态"的编队场景，广播/冗余优于单播。
- **编码与实时性**：[21] 指出重传会引入与实时性不匹配的时延，主张自适应网络编码主动注入冗余；案例中协同定位精度接近理想基线，超车中止截止时间满足率从 60% 提升到 80%。
- **无通信协同搬运**：[84] 用领导-跟随结构，跟随者只靠机载传感与预设行为维持队形，全程无机间通信；代价是队形与任务指令需要预先约定、无法实时改参考。启示：少发状态帧、多发"意图/模式"是可行的省带宽路线，与 14.2 的事件触发预算同向。

## 4.4 工程注记：ESP-NOW（非论文证据）

- 2.4 GHz、免连接、单包约 250 字节；单播可 ACK/有限重传，广播无 ACK；**无原生测距与时间同步**；peer 表与 Wi-Fi 共存会影响时延抖动。
- 建议分层：控制/模式指令（单播 + ACK + 序号，过期丢弃）；状态广播（广播 + 时间戳 + 序号，不重传）；日志/参数（低优先级、分批）。
- 建议指标：P50/P99 时延、抖动、丢包率、数据年龄，而非平均时延。
- 检索未发现以 ESP-NOW 为主题的多机器人控制论文，因此本章的 ESP-NOW 建议属于工程推断，需自行实测标定。

## 4.5 证据强度与局限

- 唯一 A 级是 [18] 的综述框架；[19]–[21] 均为 B 级，且链路与 ESP-NOW 不同（802.11 并发、编码传输）。
- 没有工作给出"广播式低速链路 + 无时间同步 + 姿态剧烈变化"的实测数据；这是 10 章 G3、G4。
- 这些论文的结论可作为设计方向，**不能当性能保证**。

## 4.6 对目标系统的启示（推断）

1. 把协同层当采样控制系统设计：先定控制频率与允许时延，再定协议与消息频率。
2. 状态类消息"要新不要全"（广播 + 过期丢弃），指令类消息"要可靠可等"（单播 + ACK）。
3. 时间同步单独解决（见 05 章 [25]），不要把"消息到达时间"当同步时钟。
4. 用数据年龄替代丢包率作为控制器的通信输入，超龄即降级（本地保持/降低编队精度）。

**本章结论**：通信研究已给出"联合设计、优先级、广播冗余、编码"四条可用原则；但 ESP-NOW 级别的实证缺失，必须自建测量与仿真标定。
