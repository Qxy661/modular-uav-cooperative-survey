# 02 模块化与可重构飞行器体系

> RQ1：多个模块如何被抽象成"一架飞机"？构型变化、对接与重构的过渡过程如何保持可控？

## 2.1 问题定义

模块化飞行器的核心矛盾是**构型的组合爆炸与控制器复用**：模块数、排布、故障状态都会改变整机动力学，但不可能为每种构型手写控制器。文献沿三条路径解决：

1. **抽象路径**：把整机映射为一个虚拟刚体（虚拟四旋翼/力旋量多面体），让现成控制器跨构型复用 [2][4]。
2. **辨识路径**：不假设已知构型，用机载 IMU/几何关系在线辨识模块相对位置与参数 [3]。
3. **规划路径**：把重构视为带稳定性约束的拆装序列规划 [6][7]；对接则作为力控问题 [4][8]。

## 2.2 方法族与代表工作

- **虚拟刚体 + 分配**：MARS-Dragonfly [4] 用"力-力矩等效、多面体约束的虚拟四旋翼"承载构型差异，再用两阶段预测分配把虚拟输入映射到模块；H-ModQuad [2] 用驱动椭球与力旋量多面体刻画不同模块组合的可控自由度。
- **构型自辨识 + 自适应**：UFO [3] 把推进/控制模块贴到任意刚性物体上，用 IMU 估计构型并自适应控制，4–8 模块托举 200–800 g。
- **重构规划**：Robust Self-Reconfiguration [6] 以"中间态可控性裕度"为约束规划拆装序列；TransforMARS [7] 把范围扩到任意形状与多重故障，先构造最小可控装配体再规划序列。
- **对接与自组装**：MARS-Dragonfly 的被动对接/磁辅助分离机构 [4]；LEGION [8] 用关节式接口与控制接触力/力矩实现零间隙互锁与 articulated 操作。
- **模块化范式**：Yim 等 [1] 给出自主性分级、对接机制分类与重构规划问题地图。

## 2.4 证据强度与局限

- 全部为 B 级（预印本）或综述（C）；没有一篇提供可复现的公开基准，数字只能作方向性参考。
- 抽象路径 [2][4] 的可迁移性依赖"模块能产生的力旋量可被参数化"；四旋翼模块的可行集合近似常值，单旋翼/倾转模块则随倾转角变化。
- 重构规划 [6][7] 的判据基于四旋翼模块，换成单旋翼模块需重做"最小可控装配体"的定义。

## 2.5 对目标系统的启示（推断）

1. **抽象层必须放在分配之前**：先定义"整机虚拟控制输入 + 可行力旋量集合"，再谈控制器。单旋翼倾转模块的可行集合应写成构型与倾转角的函数。
2. **构型自辨识可降低装配精度要求**：UFO 的 IMU 方法适合"换货物、换绑法"的场景。
3. **对接/绑缚阶段单独设计控制模式与力控**，不要塞进巡航控制器。
4. **重构判据要重新推导**：单旋翼模块在部分绑缚/部分自由的中间态，其可控性判据与四旋翼不同，这是 10 章 gap G5。

**本章结论**：模块化飞行器的成熟做法是"抽象 + 分配 + 规划"三层，但现有工作集中在四旋翼模块；单旋翼倾转模块的抽象与重构判据仍是空白。
